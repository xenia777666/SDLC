# Одна HTML-страница в браузере вместо клиента с сервером

## Контекст и постановка задачи

SRS версии 0.2 фиксирует «Полку» как замену бумажной закладке на одном компьютере. Сервера, учёта и внешних каталогов в объём не входят. Нужно выбрать форму поставки, которая не ломает эти границы и укладывается в две учебные итерации.

Вопрос: в каком виде поставлять первую версию — как настольное окно, как клиент с backend или как одну страницу в браузере?

## Драйверы решения

- Запрет отдельного сервера и сетевых запросов (SRS п. 2.3, 3.1.3).
- Срок первой версии — лабораторные итерации, без бюджета на хостинг.
- Пользователь один, ролей нет.
- Сопровождение должно быть возможным без DevOps.

## Рассмотренные варианты

- Настольное окно на Java/Swing
- SPA с backend (React + REST + СУБД)
- Одна HTML-страница в браузере

## Итог решения

Выбранный вариант: «Одна HTML-страница в браузере», потому что это единственный вариант, который сразу удовлетворяет ограничению «без сервера» и не требует установки.

### Последствия

- Хорошо, потому что нет платы за хостинг и нет учёта.
- Хорошо, потому что страница открывается в том же браузере, которым читатель и так пользуется.
- Плохо, потому что полка не переезжает на другой компьютер сама.
- Плохо, потому что нет общего backend для будущего многопользовательского режима.

### Подтверждение

В репозитории нет серверного модуля и нет запросов к сети. Сборка npm не является обязательным шагом запуска. Проверка — инспекция состава репозитория и демонстрация открытия HTML-файла.

## Плюсы и минусы вариантов

### Настольное окно на Java/Swing

Окно в духе лабораторной работы № 2.

- Хорошо, потому что не зависит от браузера.
- Плохо, потому что заказчик в SRS 0.2 уже зафиксировал веб-страницу.
- Плохо, потому что нужна установка JRE у читателя.

### SPA с backend (React + REST + СУБД)

Классическая клиент-серверная схема.

- Хорошо, потому что потом проще добавить учёт и синхронизацию.
- Плохо, потому что прямо противоречит SRS: сервер, база и сеть запрещены.
- Плохо, потому что оценка трудозатрат не помещается в две итерации.

### Одна HTML-страница в браузере

Локальный файл плюс `localStorage`.

- Хорошо, потому что совпадает с SRS п. 2.3 и 3.5.1.
- Хорошо, потому что нет сборки и секретов.
- Плохо, потому что резервного копирования между устройствами нет.
