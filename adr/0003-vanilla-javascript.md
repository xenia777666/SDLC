# Vanilla JavaScript вместо React или Vue

## Контекст и постановка задачи

На экране одна форма, список карточек и строка нормы. Сборки по окружениям в SRS нет. Нужно выбрать, на чём писать части окна, чтобы оценка итераций оставалась честной.

Вопрос: какой стек интерфейса использовать в первой версии?

## Драйверы решения

- Один экран, без маршрутизации и учёта.
- Срок — две итерации по одной неделе.
- Части уже названы в SRS: `BookForm`, `ProgressPanel`, `ShelfView`, `GoalWidget`, `LocalStore`.
- Сопровождаемость: правку должно быть видно без обхода bundler.

## Рассмотренные варианты

- React + Vite
- Vue
- Vanilla JavaScript

## Итог решения

Выбранный вариант: «Vanilla JavaScript», потому что для одного экрана фреймворк не окупает сборку и зависимости npm.

### Последствия

- Хорошо, потому что страница открывается как файл, без `npm install`.
- Хорошо, потому что junior может править разметку, не учая хуки и сборку.
- Плохо, потому что нет готовой реактивности: подписку на `LocalStore` пишем сами.
- Плохо, потому что при росте экранов придётся пересматривать решение.

### Подтверждение

В репозитории приложения нет обязательного `package.json` для запуска. Имена частей совпадают с SRS п. 2.2. Проверка — инспекция и демонстрация открытия страницы.

## Плюсы и минусы вариантов

### React + Vite

Компоненты и виртуальный DOM.

- Хорошо, потому что удобно растить интерфейс.
- Плохо, потому что появляется обязательная сборка, которой нет в SRS п. 3.5.2.
- Плохо, потому что оценка первой итерации растёт на настройку инструмента.

### Vue

Шаблоны и реактивность «из коробки».

- Хорошо, потому что шаблоны близки к HTML.
- Нейтрально, потому что для одного экрана выигрыш небольшой.
- Плохо, потому что тоже тянет сборку или runtime-скрипт с CDN, а сеть в 0.2 не нужна.

### Vanilla JavaScript

DOM напрямую, `LocalStore` как пассивная модель.

- Хорошо, потому что совпадает с «одна веб-страница без отдельного сервера».
- Хорошо, потому что имена частей SRS отображаются в файлы один к одному.
- Плохо, потому что ручная подписка на изменения.

## Дополнительная информация

Адресует REQ-PERF-ожидание «экран обновляется сразу» и п. 3.5.4 SRS. Затрагивает представления SDD 002-composition, 005-interaction, 008-patterns.
